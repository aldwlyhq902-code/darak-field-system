API) + تطبيق فني Flutter يعمل بلا إنترنت. الإصدار الحالي **0.3.0**.

## التشغيل على جهاز نظيف

### المتطلبات

| الأداة | الإصدار المستخدم | ملاحظة |
|---|---|---|
| PHP | 8.3 (NTS) | مع `pdo_pgsql`, `pdo_sqlite`, `bcmath`, `mbstring`, `gd`, `curl`, `zip`, `intl`. **`bcmath` إلزامي**: كل حساب مالي يمر عبره |
| Composer | 2.10 | |
| Node.js | 22.x | بناء أصول Vite واختبارات Playwright |
| PostgreSQL | 16+ | للإنتاج والاختبارات الملزمة. التطوير المحلي السريع يمكن أن يستخدم SQLite |
| Flutter | 3.38.7 (Dart 3.10) | لتطبيق الفني |

> على جهاز التطوير الحالي، PHP محمول في `_tools/php/php.exe` وComposer في `_tools/composer.phar`.

### الخادم

```bash
cd backend
php ../_tools/composer.phar install
cp .env.example .env
php artisan key:generate
# بيانات العرض تحتاج كلمة مرور من 16 محرفاً على الأقل في .env:
#   DARAK_DEMO_PASSWORD=<كلمة مرور للتطوير فقط>
php artisan migrate --seed
npm ci && npm run build
php artisan serve
```

حسابات العرض بعد البذر (كلمة المرور للجميع هي قيمة `DARAK_DEMO_PASSWORD`):

| الحساب | الدور |
|---|---|
| `owner@darak.test` | مالك ومشرف |
| `admin@darak.test` | إداري |
| `tech1@darak.test` … `tech4@darak.test` | فنيون (شفتان) |

البذر يرفض العمل إذا غابت `DARAK_DEMO_PASSWORD` أو قصرت عن 16 محرفاً، ويرفض بيئة
`production` كلياً. عند أول دخول للوحة يفرض النظام إعداد TOTP وحفظ رموز الاسترداد.

### تطبيق الفني

```bash
cd mobile
flutter pub get
flutter run                     # debug: يتصل بـ http://10.0.2.2:8000 (المضيف من داخل المحاكي)
```

على جهاز حقيقي مرّر `--dart-define=DARAK_API=http://<عنوان-الشبكة-المحلية>:8000`. بناء
release يرفض البدء بلا `DARAK_API` أو بعنوان غير HTTPS. تفاصيل البناء والتوقيع في
[mobile/README.md](mobile/README.md) و[mobile/android/KEYSTORE_README.md](mobile/android/KEYSTORE_README.md).

## الاختبارات

```bash
cd backend && php artisan test
```

> **تعمل على PostgreSQL، لا SQLite.** أنشئ قاعدة الاختبار مرة واحدة:
> ```bash
> createdb -U postgres darak_test
> ```
> السبب ليس تفضيلاً: كانت الاختبارات على SQLite، وهي تقبل أي نص في عمود معلن
> `uuid` ولا تُفسد المعاملة عند تعارض فهرس. خلف هذه الفجوة اختبأت **ثلاثة عيوب
> حرجة** — كل انتقال زيارة offline وكل فاتورة كانت ستفشل عند أول كتابة في
> الإنتاج بينما مجموعة الاختبارات كلها تقول إن كل شيء سليم. محرك اختبار أكثر
> تساهلاً من الإنتاج لا يختبر شيئاً ذا قيمة.
>
> للحلقة المحلية السريعة فقط:
> ```bash
> DB_CONNECTION=sqlite DB_DATABASE=:memory: php artisan test
> ```

```bash
bash _tools/smoke.sh                  # HTTP حقيقي على قاعدة مؤقتة معزولة
cd backend && npm run test:e2e        # Playwright على قاعدة مبذورة وخادم محلي
cd mobile && flutter analyze && flutter test
cd mobile && flutter test integration_test/offline_scenario_test.dart -d <device-id>   # محاكي أو جهاز
```

CI يشغّل: Pint، تدقيق Composer وnpm، اختبارات Laravel على PostgreSQL، عزل Supabase/RLS،
بناء أصول Vite، Playwright، فحص HTTP على `/up`، ثم `dart format` و`flutter analyze`
و`flutter test` وبناء APK debug. اختبار التكامل على جهاز Android لا يعمل في CI.

**عداد الاختبارات ليس رقماً يدوياً في الوثائق:** النتيجة الملزمة هي ملخص تشغيل CI على
commit الإصدار. لقطة التحقق المحلي لهذا الإصدار مذكورة مرة واحدة في
[RELEASES/0.3.0.md](RELEASES/0.3.0.md).

## قرارات معمارية ملزمة

**الفوترة تُشترى.** الخادم يحفظ مرجع المستند وحالته فقط عبر واجهة `InvoiceProvider`.
`DARAK_INVOICE_PROVIDER` يقبل قيمتين فقط: `fake` (بديل حتمي للتطوير والاختبار) و`manual`
(تُصدر الفاتورة في أداة متوافقة مع ZATCA خارج النظام ويسجل فريق المالية رقمها وتاريخها وQR
من صفحة الفواتير). أي قيمة أخرى ترمي خطأ بدل الرجوع الصامت للبديل، و`darak:preflight` يرفض
`fake`. المزود الحقيقي يُضاف كصنف جديد في `InvoiceProviderFactory`.

**الفاتورة الصادرة لا تُعدَّل.** إرجاع قطعة يصحح المخزون والتكلفة **ويطلب إشعاراً دائناً**
مرتبطاً بالفاتورة الأصلية. هذا تصحيح لخطأ في مواصفة سابقة كانت تطلب «تعديل الفاتورة».

**المال بحساب عشري، لا بأعداد عشرية ثنائية.** كل مبلغ يمر عبر `App\Support\Money` (bcmath،
تقريب نصفي، خانتان). أقساط العقد تساوي قيمته بالضبط ويمتص آخر قسط الفرق، والدفعة المقدمة جزء
من القيمة لا فوقها.

**عداد SLA يعمل داخل نافذة الخدمة فقط.** بلاغ 9:30 مساءً بمهلة 4 ساعات يستحق 9:30 صباحاً
لا 1:30 فجراً. بدون هذه القاعدة تظهر كل بلاغات المساء حمراء كل صباح.

**ساعة الجهاز تُسجَّل ولا تُصدَّق.** الجهاز يرسل الطابع الزمني + آخر وقت خادم موثوق + إزاحة
مقيسة على `elapsedRealtime` داخل الإقلاع نفسه (`BOOT_COUNT`)، وهي لا تتأثر بتغيير الساعة. الخادم
يقارنها ويَسِم التباين، ويحفظ أوقات الجهاز (UTC) بتوقيت الرياض. عند تعذر المعرفة يُرسل `null` — لا
رقم مُختلق.

**مفتاح التكرار يولّده الجهاز.** إعادة إرسال نفس `client_event_id` خمس مرات تُنتج سجلاً واحداً
وأثراً واحداً. وللإجراءات خارج المزامنة يرسل التطبيق `Idempotency-Key` محفوظاً مع الإجراء، فإعادة
المحاولة بعد انقطاع تعيد الرد المحفوظ ولا تكرر العملية.

**الصلاحيات في الخادم لا في إخفاء الأزرار.** فني يطلب زيارة زميله برابط مباشر يحصل على 403.
الإداري يصل الزيارات عبر الـAPI بصلاحية `operations` فقط، كما في اللوحة.

**عزل الشركات يفشل مغلقاً.** النماذج التشغيلية تُقيَّد بشركة المستخدم وفرعه عبر
`OperatingBranchScope`، والجدول الذي لا قاعدة له فيه لا يُرجع شيئاً بدل أن يُرجع كل شيء، والتحقق
من المعرّفات المرسلة يتم بتحميل مقيد لا بـ`exists:` عام. السجلات المرجعية (العمولات، المقاولون، الموردون، قاعدة المعرفة،
أوزان الأداء) تابعة لشركة. **كتالوج القطع مشترك عمداً** بما فيه أسعاره — قرار مفتوح للمالك في
[IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

**لا جهاز جديد بلا اعتماد.** أول جهاز للفني يُعتمد تلقائياً؛ الثاني يبقى `DEVICE_PENDING_APPROVAL`
حتى يعتمده المالك. الرمز ينتهي بعد 30 يوماً، أو بعد 14 يوماً بلا استخدام. إلغاء الجهاز أو تعطيل
الحساب يمسح بيانات العمل من الهاتف عند أول طلب.

**رفع الأدلة محدود ومتحقق منه.** التسجيل يقبل أنواع الصور المعتمدة فقط ويربط الأصل والمهمة
بالزيارة نفسها، والكتابة للجهاز الذي سجّل الدليل وحده، والرفع لا يتجاوز الحجم المعلن أو 25MiB،
وتُفحص ترويسة الصورة قبل فك ترميزها (فوق 40 ميغابكسل أو 12000 بكسل → `IMAGE_TOO_LARGE`).

**لوحة الإدارة محمية بـMFA إلزامي.** كلمة المرور وحدها لا تنشئ جلسة لوحة ولا رمز API لحساب
إداري. خمس محاولات فاشلة تقفل الحساب 15 دقيقة وتنبّه المالك، والخطوة الزمنية لـTOTP لا تُقبل
مرتين، ورموز الاسترداد تحتاج كلمة المرور ورمزاً حياً.

**الهاتف مشفّر.** قاعدة العمل SQLCipher بمفتاح 256-bit في Android Keystore، والصور والتوقيعات
AES-256-GCM بمفتاح منفصل، ولقطات الشاشة ممنوعة في release، والنسخ السحابي معطّل.

**سجل التدقيق لا يُعدَّل ولا يحمل بيانات شخصية جديدة.** سلسلة HMAC-SHA256 بمفتاح
`DARAK_AUDIT_HMAC_KEY` (لا يُغيَّر أبداً)، ومشغلات قاعدة بيانات تمنع UPDATE وDELETE وTRUNCATE،
والبيانات الشخصية تُحذف لحظة الكتابة. `php artisan darak:audit-verify` يتحقق من السلسلة.

**الإنتاج يفشل مغلقاً.** `php artisan darak:preflight` يرفض Debug وHTTP والمنصة المؤقتة وقرارات
الخصوصية الناقصة، ومزود الفوترة `fake`، والبريد غير الحقيقي، والأدلة المحلية بلا نسخة خارج الخادم،
ودور قاعدة البيانات superuser، وغياب مفتاح التدقيق أو bcmath. القائمة كاملة في
[DEPLOYMENT.md](DEPLOYMENT.md) §2.6.

**نسخة على الخادم نفسه ليست نسخة احتياطية.** `darak:backup` يشفّر بـAES-256 (`DARAK_BACKUP_PASSWORD`
إلزامي في الإنتاج)، يتحقق من الأرشيف فوراً، ينسخه خارج الخادم بـrclone، يدوّره (7 يومية · 4 أسبوعية ·
6 شهرية)، ثم يرسل نبضاً لخدمة المراقبة. أي فشل يصل صندوق المالك.

**المهام المجدولة تُطفأ ولا تُحذف.** سطر cron واحد يشغّل المجدول. أعلام `DARAK_MODULE_*` توقف
المهام المجدولة لوحدة غير أساسية دون المساس بالشاشات، والتحليلات التجريبية (تدريب نموذج الأعطال)
لا تعمل إلا بـ`DARAK_ENABLE_EXPERIMENTAL_ANALYTICS=true`، والإتلاف وفق مدد الاحتفاظ تقرير فقط حتى
يُعتمد ويُفعَّل `DARAK_RETENTION_PURGE_ENABLED`.

**موقع الفني للعميل تقريبي ومؤقت.** يرى العميل موقعاً مقرّباً (~100 م) أثناء الطريق فقط، والتقريب
في الخادم. خرائط OpenStreetMap الافتراضية نقل خارج المملكة؛ `DARAK_MAP_TILES_URL=none` يلغيها.

**لا استنتاجات قانونية في الكود.** سياسة ساعات العمل يضعها مختص في `work_policy` بإصدارات غير
قابلة للتعديل لكل شركة (الموارد البشرية ← سياسات العمل)، ويعرض الإسناد مخالفاتها. لا أرقام أجور ولا
تفسيرات مواد نظامية مثبتة في الكود.

**لا عتبة حرارة عامة.** حدود التخزين لكل صنف من ورقة المصنع (`parts.max_storage_temp_c`). العتبة
الموحدة 54°م كانت غير مثبتة — بعض المكثفات مصنفة حتى 105°م.

## الوحدات في سطور

**بوابة العميل وبلاغ QR.** لكل عميل حساب يرى منشأته فقط (`/client`، قابلة للتثبيت كـPWA عبر HTTPS)،
ومفوضون بصلاحيات ومواقع محددة. لكل موقع ملصق QR برابط عشوائي قابل للإلغاء؛ أي عامل يرفع وصفاً
وصورة بلا حساب (بحد 10 بلاغات في الساعة و30 في اليوم لكل موقع)، ويراجع المشرف البلاغ قبل تحويله
إلى زيارة. الإعداد: **العملاء ← العميل ← حسابات بوابة العميل**، ثم **طباعة QR البلاغ** بجوار الموقع.

**العروض والتحصيل.** عرض سعر بإصدارات يعتمده العميل من بوابته ثم يتحول إلى عقد وجدول دفعات شهري أو
ربع سنوي أو مخصص، مع سداد جزئي وسند قبض. العرض الذي ينشئه غير المالك تحت سعر القائمة أو الحد يحتاج
اعتماداً ثنائياً قبل إرساله. `darak:commercial-alerts` ينبّه للدفعات والعقود المنتهية.

**العمليات والجدولة.** تقويم الفنيين، اقتراح أفضل ثلاثة فنيين حسب الوردية والتخصص والتعارض والحمل
والمسافة، والإسناد النهائي بشري تعيد بوابته التحقق من القيود وسياسة العمل. الصيانة الوقائية
(`darak:maintenance-generate`)، طلب موعد من البوابة، موافقة العميل على الأعمال الإضافية (الإقفال
محجوب أثناء الانتظار)، وتقييم بعد الإغلاق يفتح متابعة عند التقييم المنخفض.

**المخزون والمشتريات.** موردون وأسعار وأوامر شراء واستلام جزئي، حجز القطع للزيارات، وتحويل بين
سيارتين لا يغيّر الرصيد حتى يقبله المستلم من التطبيق. عهدة موثقة وجرد جوال.

**الأداء والمبيعات والعمولات.** قياس الفنيين والمشرفين والفروع والمسوقين بأوزان وأهداف لكل شركة.
بوابة المسوق `/sales` (PWA) للمتابعات والمسار والعروض، لا يخزن Service Worker بيانات CRM. العمولة
مستحقة عند التحصيل، مكتسبة بعد نافذة الاسترداد، ومدفوعة بصرف من المالك فقط.

**الموارد البشرية والأسطول.** ملفات الموظفين ووثائقهم والإجازات، ملفات السيارات ووثائقها وصيانتها،
وفحص سلامة يوقف السيارة ويعيد توزيع زياراتها عند فشل عنصر حرج.

**Web Push للمسوق:** `php artisan darak:web-push-keys` مرة واحدة، ثم ضع المفتاحين في
`WEB_PUSH_VAPID_PUBLIC_KEY` و`WEB_PUSH_VAPID_PRIVATE_KEY` و`WEB_PUSH_VAPID_SUBJECT`، وفعّل التنبيهات
من **حسابي** في تطبيق المسوق عبر HTTPS.

## متغيرات البيئة

أهمها هنا؛ القائمة الكاملة بتعليقاتها في [`backend/.env.example`](backend/.env.example)، وقيم
الإنتاج في [DEPLOYMENT.md](DEPLOYMENT.md) §2.3.

| المتغير | الافتراضي | الغرض |
|---|---|---|
| `DARAK_INVOICE_PROVIDER` | `fake` | `fake` للتطوير فقط، `manual` للإنتاج؛ أي قيمة أخرى خطأ |
| `DARAK_SERVICE_START` / `DARAK_SERVICE_END` | `07:00:00` / `23:00:00` | نافذة الخدمة الافتراضية لعداد SLA |
| `DARAK_REWORK_WINDOW_DAYS` | `30` | نافذة وسم زيارة الإعادة آلياً |
| `DARAK_MAX_MEDIA_BYTES` | `26214400` | أقصى حجم لصورة أو توقيع |
| `DARAK_MAX_IMAGE_PIXELS` / `DARAK_MAX_IMAGE_SIDE` | `40000000` / `12000` | فوقها `IMAGE_TOO_LARGE` |
| `DARAK_FILES_DISK` | `local` | قرص الملفات الخاصة. `s3` يحتاج `league/flysystem-aws-s3-v3`؛ **رفع الأدلة المستأنف في 0.3.0 يحتاج قرصاً محلياً** (بند مفتوح في [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)) |
