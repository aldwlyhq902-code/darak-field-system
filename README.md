# نظام دارك — MVP

مرجع اكتمال المتطلبات: [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) — سير التطوير والتشغيل: [WORKFLOW.md](WORKFLOW.md).

منظومة إدارة عمليات صيانة ميدانية: خادم Laravel + تطبيق فني Flutter يعمل بلا إنترنت.

لشرح بصري شامل ومتوافق مع الجوال لكل واجهات النظام، افتح
[`project-overview.html`](project-overview.html) مباشرة في المتصفح.

النواة الأصلية مبنية على PRD v1.2، ثم أضيفت حزمة التشغيل والمال والمخزون والذكاء والإدارة الموضحة بندًا بندًا في [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md). ما يحتاج مزودًا خارجيًا أو اختبارًا ماديًا موضح في [HANDOVER.md](HANDOVER.md).

## التشغيل على جهاز نظيف

### المتطلبات

| الأداة | الإصدار المستخدم | ملاحظة |
|---|---|---|
| PHP | 8.3.33 (NTS) | مع `pdo_sqlite`, `pdo_pgsql`, `mbstring`, `gd`, `curl`, `zip`, `intl` |
| Composer | 2.10 | |
| Flutter | 3.38.7 (Dart 3.10) | لتطبيق الفني |
| PostgreSQL | 16+ | للإنتاج والاختبارات الملزمة. التطوير المحلي السريع يمكن أن يستخدم SQLite |

> على هذا الجهاز، نسخة PHP محمولة موجودة في `_tools/php/php.exe` وComposer في `_tools/composer.phar`
> (موقع `windows.php.net` كان معطلاً وقت التثبيت، فالنسخة من مرآة GitHub الرسمية).

### الخادم

```bash
cd backend
php ../\_tools/composer.phar install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan serve
```

بيانات الدخول التجريبية بعد البذر:

| الحساب | الدور |
|---|---|
| `owner@darak.test` | مالك ومشرف |
| `tech1@darak.test` … `tech4@darak.test` | فنيون (شفتان) |
| `admin@darak.test` | إداري |

كلمة المرور للجميع: `password` — **للتطوير فقط**.

عند أول دخول إلى لوحة الإدارة يفرض النظام إعداد TOTP وحفظ رموز الاسترداد. بذر
البيانات التجريبية مرفوض برمجياً إذا كانت البيئة `production`.

### تطبيق الفني

```bash
cd mobile
flutter pub get
flutter run --dart-define=DARAK_API=http://10.0.2.2:8000
```

`10.0.2.2` هو عنوان جهاز المضيف من داخل محاكي أندرويد. على جهاز حقيقي استبدله بعنوان الشبكة المحلية.

## الاختبارات

```bash
cd backend && php artisan test
```

> **تعمل على PostgreSQL، لا SQLite.** أنشئ قاعدة الاختبار مرة واحدة:
> ```bash
> createdb -U postgres darak_test
> ```
> السبب ليس تفضيلاً: كانت الاختبارات على SQLite، وهي تقبل أي نص في عمود معلن
> `uuid` ولا تُفسد المعاملة عند تعارض فهرس. خلف هذه الفجوة اختبأت **ثلاثة عيوب
> حرجة** — كل انتقال زيارة offline وكل فاتورة كانت ستفشل عند أول كتابة في
> الإنتاج بينما 136 اختباراً تقول إن كل شيء سليم. محرك اختبار أكثر تساهلاً من
> الإنتاج لا يختبر شيئاً ذا قيمة.
>
> للحلقة المحلية السريعة فقط:
> ```bash
> DB_CONNECTION=sqlite DB_DATABASE=:memory: php artisan test
> ```

```bash
cd mobile && flutter test
```

```bash
bash _tools/smoke.sh
```

يشغّل CI اختبارات Laravel على PostgreSQL، ثم يبني أصول Vite، ويفتح الخادم مؤقتاً
ويتحقق من `/up` عبر HTTP. كما يبني APK debug بعد تحليل واختبارات Flutter. التحقق
الميداني بالكاميرا والموقع ووضع الطيران يبقى خطوة إصدار على هاتف حقيقي.

**عداد الاختبارات ليس رقماً يدوياً في الوثائق:** النتيجة الملزمة هي ملخص آخر تشغيل ناجح لـCI على commit الإصدار؛ يشغّل Laravel على PostgreSQL واختبارات Flutter وبناء الويب وAPK وفحص HTTP الصحي.

## البنية

```

  app/Services/          منطق العمل: المزامنة، الحالات، SLA، المخزون، الفوترة
  app/Http/Controllers/  طبقة رقيقة فوق الخدمات

mobile/                  تطبيق Flutter — Offline-first
  lib/core/              الطابور، محرك المزامنة، الساعة الموثوقة، قاعدة البيانات المحلية
  lib/screens/           الدخول، زيارات اليوم، الزيارة، حالة المزامنة
  test/                  اختبارات محرك المزامنة على SQLite حقيقي

_tools/                  PHP محمول + Composer + سكربت الـsmoke
```

## قرارات معمارية ملزمة

**الفوترة تُشترى.** الخادم يحفظ مرجع المستند وحالته فقط. `InvoiceProvider` واجهة، و`FakeInvoiceProvider` بديل حتمي للاختبار. التبديل للمزود الحقيقي سطر واحد في `DarakServiceProvider`.

**الفاتورة الصادرة لا تُعدَّل.** إرجاع قطعة يصحح المخزون والتكلفة **ويطلب إشعاراً دائناً** مرتبطاً بالفاتورة الأصلية. هذا تصحيح لخطأ في مواصفة سابقة كانت تطلب «تعديل الفاتورة».

**عداد SLA يعمل داخل نافذة الخدمة فقط.** بلاغ 9:30 مساءً بمهلة 4 ساعات يستحق 9:30 صباحاً لا 1:30 فجراً. بدون هذه القاعدة تظهر كل بلاغات المساء حمراء كل صباح.

**ساعة الجهاز تُسجَّل ولا تُصدَّق.** الجهاز يرسل الطابع الزمني + آخر وقت خادم موثوق + إزاحة رتيبة لا تتأثر بتغيير الساعة. الخادم يقارنها ويَسِم التباين. عند تعذر المعرفة يُرسل `null` — لا رقم مُختلق.

**مفتاح التكرار يولّده الجهاز.** إعادة إرسال نفس `client_event_id` خمس مرات تُنتج سجلاً واحداً وأثراً واحداً. هذا ما يجعل إعادة المحاولة بعد انقطاع آمنة.

**الصلاحيات في الـAPI لا في إخفاء الأزرار.** فني يطلب زيارة زميله برابط مباشر يحصل على 403.

**رفع الأدلة محدود ومتحقق منه.** التسجيل يقبل أنواع الصور المعتمدة فقط، ويربط الأصل والمهمة بالزيارة نفسها، والرفع لا يستطيع تجاوز الحجم المعلن أو حد 25MiB. مسارات الرفع محدودة المعدل.

**لوحة الإدارة محمية بـMFA إلزامي.** كلمة المرور وحدها لا تنشئ جلسة لوحة، ورموز
الاسترداد أحادية الاستخدام ومخزنة كـhash، وسر TOTP مشفر داخل قاعدة الخادم.

**قاعدة الهاتف مشفرة بـSQLCipher.** مفتاح عشوائي 256-bit محفوظ في مخزن مفاتيح
النظام، مع ترحيل تلقائي للقاعدة القديمة ونسخة رجوع لا تُحذف قبل التحقق.

**بوابة العميل PWA وبلاغ QR.** لكل عميل حساب مستقل يرى بيانات منشأته فقط، ويمكن
تثبيت البوابة على الجوال. لكل موقع ملصق QR برابط عشوائي قابل للإلغاء؛ يستطيع أي
عامل فتحه بلا حساب ورفع وصف وصورة، ثم يراجع المشرف البلاغ قبل تحويله إلى زيارة.

تشغيلها بعد التحديث:

1. نفّذ `php artisan migrate --force` لإضافة حسابات البوابة والبلاغات ورمز كل موقع.
2. من لوحة الإدارة افتح **العملاء ← العميل ← حسابات بوابة العميل** وأنشئ بيانات الدخول.
3. بجوار الموقع اختر **طباعة QR البلاغ**، ثم اطبع الملصق وثبّته في المحل.
4. تظهر البلاغات الجديدة في **البلاغات الطارئة**؛ يراجعها المشرف ثم يرفضها بسبب مسجل أو يحولها إلى زيارة عاجلة ويسند الفني.
5. يدخل العميل من `/client`، ويمكنه تثبيت البوابة من المتصفح على الجوال. يتطلب التثبيت في الإنتاج اتصال HTTPS صالحاً.

**العروض والتحصيل والتشغيل التجاري.** من صفحة **العروض والتحصيل** تنشئ مسودة عرض
سعر مرتبطة بمواقع العميل، ثم ترسلها للعميل ليعتمد الإصدار من بوابته. التحويل ينشئ
عقداً وجدول دفعات شهرياً أو ربع سنوي، وتدعم الدفعة سداداً جزئياً أو كاملاً وسند قبض.
المهمة اليومية `darak:commercial-alerts` تضع تنبيهات الدفعات القادمة والمتأخرة
والعقود التي قاربت نهايتها في صندوق الإشعارات.

**العهد والجدولة والمؤشرات.** صفحة الفريق توثق تسليم سيارة أو جهاز أو أداة أو مخزون
سيارة للفني، وقبولها وإرجاعها مع وصف الحالة. صفحة **الجدولة والمؤشرات** تعرض تقويم
الفنيين الأسبوعي، الزيارات غير المسندة، الأصول ذات الأعطال المتكررة والقطع كثيرة
الصرف. المؤشرات قواعد تاريخية شفافة؛ التنبؤ الإحصائي الحقيقي مؤجل حتى تتوفر عينة
تشغيل موثوقة وكافية.

**المشتريات والمخزون المتقدم.** صفحة **المشتريات والحجوزات** تدير الموردين وأسعارهم
ومدة التوريد، وأوامر الشراء والاستلام الجزئي أو الكامل إلى المستودع. يمكن حجز قطعة
لزيارة قادمة، فينخفض الرصيد المتاح لبقية الزيارات والتحويلات، ويستهلك الفني الحجز
عند صرفها على الزيارة. تحويل المخزون بين سيارتين لا يغيّر الرصيد حتى يقبله الفني
المستلم من التطبيق، أو يعتمده المالك كاستثناء إداري.

**موافقة الأعمال الإضافية.** يرسل المشرف من صفحة الزيارة وصف العمل وقيمته قبل
الضريبة، فيظهر فوراً في بوابة العميل للموافقة أو الرفض. يظل إقفال الزيارة محجوباً
أثناء انتظار القرار، ويصل القرار وحالة الحجز إلى تطبيق الفني ضمن مزامنة الزيارة.

**الصيانة الوقائية والمواعيد والتوزيع.** صفحة **الصيانة الوقائية** تنشئ خطة مرتبطة
بالعقد والموقع وأصل محدد أو كل أصول الموقع. تنفذ المهمة `darak:maintenance-generate`
يوميًا الساعة 05:00، وتولد الاستحقاق مرة واحدة ثم تقدم التاريخ التالي. يستطيع العميل
طلب موعد خلال 14 يومًا من بوابته مع سعة تقديرية للفترات، ويبقى الطلب معلقًا حتى يحوله
المشرف إلى زيارة أو يرفضه بسبب مسجل. تعرض صفحة الجدولة أفضل ثلاثة فنيين متاحين حسب
الوردية والتخصص والتعارض والحمل والمسافة التقريبية من مهام اليوم؛ والإسناد النهائي
يبقى قرارًا بشريًا وتعيد بوابة الإسناد التحقق من القيود.

**التقييم والشكوى.** بعد إغلاق الزيارة يستطيع العميل إرسال تقييم واحد. التقييم 1–2
أو تأكيد أن العطل لم يُحل يفتح متابعة للمشرف ويرسل تنبيهًا، ولا يغلق سجل المتابعة إلا
بملاحظة موثقة في سجل التدقيق.

**قياس الأداء والترتيب.** صفحة **الأداء والترتيب** تقيس الفنيين والمشرفين والفروع
والمسوقين أسبوعيًا أو شهريًا أو ربع سنوي أو خلال فترة مخصصة. تجمع الدرجة بين SLA
والإصلاح من أول مرة ورضا العميل وجودة التوثيق والتكلفة والتحصيل والربحية والتحويل
التجاري بحسب الفئة. تعرض المقارنة بالفترة السابقة ونقاط القوة وأولوية التطوير، وتمنع
العينات القليلة من رفع أو خفض الترتيب بصورة مضللة. يستطيع المالك ضبط وزن كل مؤشر
وهدفه والحد الأدنى لعينته، وتُسجل التغييرات في سجل التدقيق. يتوفر تصدير CSV متوافق
مع Excel وتقرير PDF للإدارة، مع صلاحية مستقلة باسم `performance`.

**تطبيق المسوق PWA.** المسار `/sales` يفتح بوابة جوال قابلة للتثبيت للمسوق، تشمل
أولويات اليوم، الاتصال وWhatsApp، مسار المبيعات، تسجيل المتابعة وتغيير المرحلة،
إنشاء عرض السعر وإرساله، المبيعات والتحصيل والعمولة ودرجة الأداء الشهرية. المسوق
يرى فرصه وعروضه فقط، مع عزل إضافي حسب الفرع، بينما يستطيع المالك متابعة الفريق.
الصلاحية المستقلة هي `sales` وتُمنح من صفحة الإدارة. صفحات CRM تعمل عبر الشبكة فقط؛
لا يخزن Service Worker أسماء العملاء أو أرقامهم أو قيم العروض بعد تسجيل الخروج.
يتطلب تثبيت PWA في الإنتاج HTTPS صالحًا.

**إنتاجية المبيعات والتنبيهات.** يستطيع المسوق تحويل الفرصة المكتسبة إلى عميل
وموقع وجهة اتصال دون إعادة إدخال، وإرفاق PDF والصور والملاحظات الصوتية في تخزين
خاص. تسجل الفرصة المصدر والحملة وتاريخ الإغلاق المتوقع، ويحدث النظام احتمال الفوز
بصورة شفافة حسب المرحلة وعدد المتابعات. تعرض البوابة تقويم 30 يومًا، وتكشف الفرص
الراكدة، وتسمح للمالك بتحديد أهداف المكالمات والاجتماعات والعروض والمبيعات والتحصيل.
طلب الخصم لا يغيّر قيمة العرض؛ بل يدخل دورة الاعتماد المالي الثنائي. تنفذ المهمة
`darak:sales-alerts` كل ساعة، وتُرسل Web Push للمتابعات المستحقة والعروض القريبة من
الانتهاء عند تهيئة VAPID، مع صندوق تنبيهات داخل التطبيق دائمًا. وللتفعيل:

1. نفّذ `php artisan darak:web-push-keys` مرة واحدة.
2. ضع المفتاحين في `WEB_PUSH_VAPID_PUBLIC_KEY` و`WEB_PUSH_VAPID_PRIVATE_KEY`، واضبط `WEB_PUSH_VAPID_SUBJECT` ببريد المؤسسة.
3. افتح تطبيق المسوق عبر HTTPS واختر **حسابي ← تفعيل تنبيهات الجهاز**.

**الإنتاج يفشل مغلقاً.** `php artisan darak:preflight` يرفض Debug وHTTP وCookie غير الآمنة والرموز غير المحدودة وPostgreSQL غير المضبوط والنسخ الاحتياطي غير المشفر أو الموجود داخل مجلد النشر، ويرفض المنصة المؤقتة وقرارات الخصوصية/الاحتفاظ الناقصة.

**أرشيف النسخ الاحتياطي مشفر.** في الإنتاج يلزم `DARAK_BACKUP_PASSWORD` بطول 20 محرفاً على الأقل، وتُشفّر كل مكونات ZIP بـAES-256 قبل كتابتها.

**لا استنتاجات قانونية في الكود.** سياسة ساعات العمل تأتي من مختص معتمد عبر `work_policy` قابلة للإصدار. لا أرقام أجور ولا تفسيرات مواد نظامية مثبتة في الكود.

**لا عتبة حرارة عامة.** حدود التخزين لكل صنف من ورقة المصنع (`parts.max_storage_temp_c`). العتبة الموحدة 54°م كانت غير مثبتة — بعض المكثفات مصنفة حتى 105°م.

## متغيرات البيئة

| المتغير | الافتراضي | الغرض |
|---|---|---|
| `DARAK_INVOICE_PROVIDER` | `fake` | مزود الفوترة الإلكترونية |
| `DARAK_SERVICE_START` | `07:00:00` | بداية نافذة الخدمة الافتراضية |
| `DARAK_SERVICE_END` | `23:00:00` | نهايتها |
| `DARAK_REWORK_WINDOW_DAYS` | `30` | نافذة وسم زيارة الإعادة آلياً |
| `DARAK_MAX_MEDIA_BYTES` | `26214400` | الحد الأعلى للصورة أو التوقيع الواحد |
| `SANCTUM_EXPIRATION` | `43200` | عمر رمز الجهاز بالدقائق، 30 يوماً افتراضياً |
| `DARAK_BACKUP_PASSWORD` | بلا افتراضي | مفتاح تشفير النسخة الاحتياطية؛ إلزامي في الإنتاج |
| `DARAK_BACKUP_PATH` | داخل التخزين محلياً | مسار خارجي إلزامي في فحص الإنتاج |
| `DARAK_ENABLE_EXPERIMENTAL_ANALYTICS` | `false` | إظهار ترتيب الأداء وتنبؤ الأعطال التجريبيين بعد اعتماد المالك فقط |
